# Data Authority Matrix

Date: 2026-07-24

This matrix records the current canonical write/read authority after the
dual-track cleanup. Code and `server/migrations/0001_baseline.sql` remain the
source of truth when this document and implementation disagree.

| Domain | Canonical Authority | Derived / Audit Only | Retired / Non-Authority |
|---|---|---|---|
| Evidence candidates | `extracted_evidence` plus `evidence_links` with `context_candidate`, `supports`, `contradicts`, `derived_from`, or `mentions`; context selection must pass current source read policy before injection. | `evidence_links.link_type='used_in_context'` is best-effort run audit only. | `evidence_links.link_type='provenance'` is retired and is not a source lineage authority. |
| Curated evidence | `sources`, `knowledge_item_sources`, and `claim_sources` after proposal acceptance. | `source_refs_json` snapshots are frozen display/audit context. | Runtime candidate evidence cannot become curated evidence without proposal acceptance. |
| Provenance | `provenance_links` for accepted object/source lineage. | Run/materialization events may mention source ids for audit. | KnowledgeItem shortcut source columns are removed. |
| Relations | `object_relations` is the only canonical FK-backed graph for Knowledge, Claim, and Source relations. | `retrieval_edges` is a projection rebuilt from active `object_relations` and curated source links. `note_links` is direct working-note UI linkage and is not canonical graph authority. | `entity_links`, `knowledge_item_relations`, `claim_relations`, and `knowledge_relation_*` / `claim_relation_*` proposal types are retired. |
| Memory taxonomy | `memory_entries.memory_type` is the public category; `memory_entries.memory_layer` is the hierarchy/layer. `created_from_proposal_id` is the proposal FK. | Cross-person Memory rows in `content_access_logs` and provenance rows are audit/read traces. | `memory_access_logs`, `memory_kind`, `memory_entries.source_proposal_id`, `memory_entries.scope_id`, and `memory_entries.capability_id` are retired. |
| Context preparation | `RuntimeContextInvocationGateway` is the authority for all managed Run planning, including direct Chat and Room turns, live reacquisition, Delivery, and safe Invocation Snapshot lifecycle. Bounded internal provider tasks retain domain-owned prompts behind the common provider-task control/delivery/snapshot/Usage boundary. | Invocation Snapshots and provider-task snapshots are immutable safe audit read models. Normal Run/Trace reads expose only their safe projection; raw replay, when policy permits it, remains a separately authorized Sealed Payload. | Managed adapters and Chat/Room routes cannot fetch, reorder, rebudget, or independently assemble model-visible context. No legacy builder, route-owned bundle, or snapshot fallback remains. |
| Project Kernel | `projects` and immutable `project_brief_versions` own Project identity and the active Brief. There is no Project type field (ADR 0019); creation presets nothing else. | Overview, Attention, entity summaries, Delivery, and Operations are registered projections over owning domains. | A Project type, a creation-time Template, one Project-wide research question, or mode-driven object conversion is not authoritative. |
| Inquiry | `inquiry_threads` plus kind-specific state, statement revisions, Iterations, work state, typed Thread relations, Signals, Candidates, and Review Packets own evolving Questions/Hypotheses and reviewed cognitive change. | Inquiry/Combined graph output, Delta Briefs, Overview, and Attention are read projections. | `projects.current_focus`, graph nodes, Notes, and Auto Research workflow state are not Question authorities. |
| Project Research | Each `project_research_workflows` row owns one version-pinned Question scope. A fresh immutable `workflow_executions` pass is the sole orchestration authority for each retry/resume/reconcile event; `project_operations` and checkpoints are long-lived domain projections. | Reports, scan summaries, matrices, step states, and monitoring summaries are derived/audit records. | The removed cyclic state machine, Project-level question authority, and any second operation execution engine have no compatibility path. |
| Experiments | Experiment Definitions, immutable Versions, Experiment Runs with frozen config, Observations, and reviewed Interpretations own experimental meaning and lifecycle. Governed `runs` own managed executor terminal output. | Parsed managed metrics become cited Observations; converted Interpretations propose Inquiry Signals. | The retired Experiment Campaign model and a second Experiment state machine are non-authorities. |
| Knowledge promotion | `knowledge_promotion_candidates`, bounded packet membership, immutable source references, and revalidation events own promotion review state. Accepted promotion Proposals remain the only path to canonical Knowledge writes. | AI extraction Runs and `domain_change_outbox` are provenance/delivery infrastructure. Project Review is ephemeral composition only. | Extraction, revalidation, or Project Review cannot directly create or overwrite canonical Knowledge. |
| Decisions | Decision Cases, Options, Criteria, Scores, Commitments, and explicit source Thread references own decision state. | Decision Overview/Attention and a Commitment-created Delivery Task are projections/outputs into their owning domains. | Switching Project Mode does not convert Inquiry data into Decision data. |
| Learning | Learning Objectives/Items own learning design; per-user mastery/review state owns scheduling progress and pins shared Knowledge versions. | Project Learning Overview/Attention is a contextual projection. | Learning does not own or duplicate canonical Knowledge and is not a Project Mode-only data silo. |
| Delivery / Operations | Tasks own Delivery work. Automations, Runs, and operational-alert Activity own current Operations inputs. | Project Delivery/Operations Overview, Attention, and Area pages are ACL-filtered composition adapters. | There are no Delivery or Operations aggregate tables; Incident/Runbook objects do not exist until a demonstrated lifecycle requires them. |
| Run execution | `runs` owns terminal status/output. `run_events` is append-only fact audit. `run_steps` is lifecycle summary. | Step/event writes are best-effort and must not block terminal writes. | Step/event failure must not overwrite or mask terminal run status. |
| Execution topology | `machines` owns physical-device identity; `hosts` owns ExecutionHost identity/liveness/capabilities; `workspace_locations` owns a physical checkout, its git observations, lifecycle status, and persisted `execution_ready`. `project_folders` remains the logical repository identity. | Daemon heartbeat payloads and host-list machine labels are transport/read projections; Run `project_folder_id` is a write-once logical denormalization of its Location. A Folder has at most one active Location for new work; stale Locations remain eligible only for initialized Conversations already pinned to them, while archived Locations are non-executable. | A Conversation pins its own Primary Location or managed workspace. The retired Folder-level `preferred` flag, old host/path columns, host-derived readiness, and any server attempt to resolve a remote path are not authorities. |
| Project Conversation execution | `conversation_execution_contexts` owns one Conversation's Host, Primary Workspace, initialization state, dispatch lock/queue state, and immutable Host/Primary choice. `session_conversation_backends` has exactly one row per Conversation × Agent and owns the pinned profile plus its initialization-time model/provider and runtime configuration/policy snapshot; `bound_by_user_id` is attribution/credential ownership, never an authorization or runtime-continuity partition, is not part of the grain, and cannot cascade-delete the pin. Conversation-shaped `host_threads` owns the Host/CLI/workspace pin and vendor continuity. `conversation_folder_access_grants` owns concrete same-Host attachment grants. | Preflight candidates use the canonical daemon-reported Host execution-target projection; a reusable Agent runtime profile is reused or materialized atomically at initialization. Access-filtered runtime summaries, Host heartbeats, and Folder metadata are read projections. Timeline system events and Run snapshots are immutable audit/provenance records. Trusted remote Hosts may honor explicit write attachments; server-host attachments remain read-only behind the managed worktree/patch boundary. | Room roster, mutable Agent runtime defaults/profiles, a Folder's active Location, and mutable UI selections cannot choose, reconfigure, or replace an initialized Conversation execution context. |
| Task execution advancement | The shared Run-terminal → Task-status projector owns automatic `done`/`blocked` advancement after all linked Runs are hard-terminal. | Task board/area views are read projections; `task_runs` links Tasks to Runs. | A dispatch route or one execution transport may not maintain a second Task lifecycle path. |
| Artifacts/proposals from runs | `RunMaterializationService` owns artifact/proposal materialization and applies `artifact.persist` / `proposal.create` policy gates before durable INSERT. | Materialization errors are recorded in `run.output_json.materialization_errors`; successful adapter runs with partial materialization failure are `degraded`. | Adapter output does not directly mutate active Knowledge, Claim, Memory, or relations. |
| Capabilities | Product capability read API is `/api/v1/capability-definitions`; built-ins come from `server/src/modules/capabilities/registry.ts`. | Workflow/catalog compatibility data is internal unless exposed through framework APIs. | Legacy public `/api/v1/capabilities*` product route and frontend `capabilitiesApi` are retired. |
| Identity / space context | User identity comes from auth; active space comes from explicit request context such as `X-Rainver-Space-Id` or path scope. | Query `space_id` is legacy fallback on some backend readers only. | The frontend must not globally append `space_id` / `user_id` query params or keep `default_user` client state. |
